# 1. Conexão da conta do Telegram, bot de notificações e responsabilidade de uso

A plataforma deve operar com duas integrações isoladas:

1. Uma sessão da conta pessoal do Telegram do cliente, criada somente após consentimento explícito por QR Code e utilizada exclusivamente para leitura dos grupos autorizados;
2. Um bot central do Telegram, criado e administrado pela empresa responsável pelo SignalWatch, utilizado exclusivamente para enviar notificações privadas.

Deve existir uma única configuração oficial do bot de notificações para o MVP, compartilhada de forma segura entre os clientes, com isolamento rigoroso dos grupos, sessões, alertas e dados de cada organização.

O bot de notificações deverá ser criado previamente pela empresa responsável no próprio Telegram por meio do `@BotFather`. O responsável pela operação fornecerá o token desse bot para a configuração inicial da aplicação, exclusivamente através de secrets ou mecanismo equivalente. O token nunca deverá ser solicitado, exibido ou enviado pelo cliente.

A leitura dos grupos não deverá depender do bot de notificações. Ela deverá utilizar a conta pessoal do Telegram do próprio cliente, conectada mediante QR Code gerado por uma integração compatível com a API de cliente do Telegram. A plataforma deve deixar claro que o cliente está autorizando uma sessão da própria conta pessoal.

A plataforma não deve:

- Solicitar senha, código SMS ou código de login diretamente na plataforma;
- Acessar a conta pessoal do Telegram sem consentimento explícito;
- Acessar contas de terceiros;
- Permitir que cada cliente crie ou conecte seu próprio bot de notificações;
- Permitir conexão silenciosa ou não autorizada da conta pessoal;
- Monitorar grupos que não estejam disponíveis para a conta pessoal autorizada;
- Expor a sessão da conta pessoal, o token do bot ou qualquer credencial na interface, nos logs, nas respostas da API ou em mensagens de erro;
- Enviar mensagens automaticamente para grupos;
- Entrar em contato automaticamente com participantes;
- Responder ou negociar em nome do cliente;
- Enviar publicidade para os grupos;
- Adicionar participantes;
- Criar conversas automáticas;
- Agir como se fosse o cliente.

O objetivo da plataforma é exclusivamente:

1. Utilizar a sessão da conta pessoal do Telegram autorizada pelo próprio cliente;
2. Processar somente mensagens dos grupos selecionados pelo cliente e disponíveis para essa conta;
3. Identificar mensagens que correspondam às regras configuradas;
4. Exibir alertas dentro da plataforma;
5. Enviar uma cópia do alerta para o chat privado do próprio cliente através do bot oficial de notificações, depois que o cliente iniciar uma conversa com esse bot.

A configuração técnica do bot de notificações deve acontecer antes da disponibilização do produto, pelo responsável da plataforma, usando o token fornecido de forma segura. A configuração da conta pessoal deve acontecer somente após o cliente escanear o QR Code e confirmar a autorização no próprio aplicativo do Telegram. O cliente não deve informar ou visualizar o token do bot.

Antes de implementar os conectores, valide:

- A API de cliente do Telegram ou provedor compatível que permita autorização via QR Code;
- A leitura das mensagens dos grupos acessíveis pela conta pessoal;
- O armazenamento e a renovação segura da sessão autorizada;
- A Telegram Bot API para envio das notificações;
- O uso de webhook ou long polling para o bot de notificações;
- A geração de links diretos para as mensagens;
- As limitações, políticas e permissões aplicáveis a cada integração.

Não crie uma integração falsa, simulada ou baseada em acesso oculto.

Caso a API de cliente do Telegram, a sessão autorizada, as permissões da conta ou a Telegram Bot API impeçam a implementação real, interrompa essa parte e apresente claramente a limitação. Não crie uma tela que aparente estar funcionando quando a integração real não estiver disponível.

O responsável pela plataforma é responsável por:

- Criar e administrar o bot oficial de notificações no `@BotFather`;
- Manter o token do bot em secrets;
- Configurar e manter o webhook ou mecanismo de recebimento de atualizações do bot;
- Escolher e configurar o conector seguro para sessões de contas pessoais;

O cliente é responsável por:
- Autorizar a própria conta do Telegram através do QR Code;
- Manter o acesso aos grupos que deseja monitorar;
- Selecionar os grupos que deseja monitorar;
- Criar as regras;
- Definir as palavras-chave;
- Utilizar os alertas de forma responsável;
- Decidir se entrará em contato manualmente com o autor de uma publicação.

A plataforma não deve criar uma etapa operacional exigindo o consentimento individual de cada participante dos grupos.

O consentimento e a responsabilidade de uso da plataforma devem estar concentrados no cliente que:

- Cria a conta;
- Paga pelo plano e acessa a plataforma;
- Autoriza a sessão da própria conta do Telegram;
- Inicia uma conversa privada com o bot oficial de notificações;
- Escolhe os grupos;
- Configura as regras;
- Recebe os alertas.

Os termos de uso e a política de privacidade devem explicar de forma transparente que:

- A conta pessoal do Telegram do cliente será conectada somente após consentimento explícito via QR Code;
- A sessão autorizada poderá disponibilizar mensagens dos grupos acessíveis à conta e selecionados pelo cliente;
- O bot oficial de notificações é criado e administrado pela empresa responsável;
- Os alertas serão enviados ao chat privado do cliente através desse bot;
- A plataforma não acessará contas de terceiros nem enviará mensagens automáticas aos grupos;
- A disponibilidade das mensagens depende das permissões, da sessão e das configurações do Telegram.

## Etapa 4 — Conexão autorizada da conta pessoal do Telegram

A integração técnica do bot de notificações já deve estar configurada pela empresa responsável. Nesta etapa, o cliente autoriza a sessão da própria conta pessoal do Telegram para que a plataforma possa ler os grupos aos quais essa conta tem acesso. O cliente não deve fornecer senha, código de login ou token.

Fluxo:

1. Exibir uma explicação clara sobre quais dados serão acessados e por quê;
2. Informar que o QR Code autoriza somente a própria conta do cliente e não conecta contas de terceiros;
3. Gerar um QR Code real pela integração de cliente do Telegram, com validade e expiração;
4. Orientar o cliente a abrir o Telegram em outro dispositivo e escanear o QR Code;
5. Aguardar a confirmação da autorização no aplicativo oficial do Telegram;
6. Confirmar a sessão sem solicitar senha, código SMS ou código de login na plataforma;
7. Exibir somente informações não sensíveis da conta autorizada, preferencialmente nome e username mascarados;
8. Detectar os grupos disponíveis para a conta autorizada;
9. Orientar o cliente a iniciar uma conversa privada com o bot oficial de notificações;
10. Permitir que o cliente escolha quais grupos deseja monitorar;
11. Aguardar e validar a chegada de mensagens reais;
12. Exibir o status atualizado da sessão e do bot de notificações.

Estados da conexão da conta pessoal:

- QR Code aguardando leitura;
- QR Code expirado;
- Aguardando confirmação no aplicativo do Telegram;
- Sessão autorizada;
- Sessão expirada;
- Sessão revogada;
- Conta desconectada;
- Erro de autenticação;
- Conta sem acesso ao grupo;
- Grupo indisponível;
- Conector de conta pessoal temporariamente indisponível;
- Bot de notificações indisponível;
- Falha ao entregar alerta privado.

Nunca solicitar ao cliente na plataforma:

- Senha do Telegram;
- Código SMS;
- Código de autenticação da conta pessoal;
- Token do bot oficial de notificações;
- Dados de outra conta.

A tela deve deixar claro que a conta pessoal do cliente será acessada somente após o consentimento via QR Code, que o bot oficial de notificações é administrado pela empresa responsável, que nenhum token será solicitado ao cliente e que a plataforma não realiza contato automático com os participantes.

# 8. Processamento das mensagens

Quando uma nova mensagem autorizada chegar:

1. Normalizar o texto;
2. Avaliar as regras ativas;
3. Identificar quais palavras-chave foram encontradas;
4. Identificar o grupo correspondente;
5. Verificar se a mensagem não é duplicada;
6. Registrar o evento;
7. Criar uma notificação dentro da plataforma;
8. Enviar uma cópia para o chat privado do próprio cliente no Telegram através do bot oficial, depois que o cliente tiver iniciado conversa privada com ele;
9. Registrar o resultado do envio.

O sistema deve preservar a mensagem original sem alterar seu significado.

Exemplo:

“Alerta encontrado

Grupo: Oportunidades Comerciais

Regra: Clientes interessados

Palavra encontrada: orçamento

Mensagem original:
‘Alguém conhece uma empresa que faça orçamento para implantação de CRM?’

Data: 12/08/2026 às 14:32”

# 9. Notificações

As notificações devem ser destinadas exclusivamente ao cliente que configurou a plataforma.

Quando uma mensagem corresponder a uma palavra-chave:

1. Criar uma notificação dentro da plataforma;
2. Exibir a mensagem original;
3. Informar o grupo de origem;
4. Informar a regra acionada;
5. Informar a palavra-chave encontrada;
6. Enviar uma cópia para o chat privado do próprio cliente através do bot oficial de notificações;
7. Incluir um botão ou link “Abrir mensagem” apontando para a mensagem original quando o Telegram disponibilizar um link compatível;
8. Informar claramente quando a mensagem não puder ser aberta por falta de acesso ao grupo, mensagem privada ou restrição do Telegram;
9. Registrar o status de entrega.

A plataforma não deve:

- Enviar mensagens para o grupo monitorado;
- Responder ao autor da publicação;
- Iniciar uma conversa automaticamente;
- Negociar produtos ou serviços;
- Enviar publicidade;
- Revelar ao autor da publicação que ele foi monitorado;
- Agir em nome do cliente;
- Fazer follow-up automático.

O cliente poderá analisar a mensagem e, se desejar, entrar em contato manualmente com o autor da publicação utilizando seus próprios meios.

Tipos de notificação:

- Nova mensagem encontrada;
- Regra acionada;
- Falha na entrega;
- Conexão perdida;
- Bot desativado ou integração revogada;
- Pagamento pendente;
- Limite do plano próximo do fim;
- Plano bloqueado.

# 15. Privacidade e segurança

A plataforma deve processar somente as mensagens disponibilizadas pela sessão autorizada da conta pessoal do cliente nos grupos que ele escolher para monitoramento.

Implementar:

- Isolamento de dados por conta e organização;
- Controle de acesso em todas as requisições;
- Criptografia do token central do bot e das sessões das contas pessoais;
- Não armazenar o token central do bot ou as sessões pessoais em texto puro;
- Não permitir que o token do bot ou as sessões pessoais sejam enviados ao frontend ou expostos ao cliente;
- Permitir revogação e exclusão da sessão pessoal a qualquer momento;
- Não reutilizar uma sessão pessoal em outra organização;
- Minimizar a retenção de mensagens;
- Permitir configurar o prazo de retenção;
- Registrar auditoria das ações importantes;
- Proteger webhooks;
- Validar assinaturas dos webhooks do Telegram quando aplicável;
- Impedir acesso de uma organização aos grupos, mensagens e alertas de outra organização;
- Impedir processamento de grupos que não estejam disponíveis para a sessão pessoal autorizada;
- Permitir exclusão dos dados do cliente;
- Informar claramente quais dados são processados;
- Nunca vender ou compartilhar mensagens;
- Nunca usar as mensagens para criar perfis externos dos participantes;
- Nunca enviar mensagens automáticas aos participantes;
- Nunca criar campanhas automáticas a partir das mensagens;
- Limitar o acesso interno aos dados;
- Criar logs de acesso e alterações importantes.

A plataforma deve deixar claro que o cliente controla:

- Qual conta pessoal do Telegram será autorizada;
- Quais grupos serão monitorados;
- Quais palavras-chave serão utilizadas;
- Por quanto tempo os alertas serão armazenados;
- Quais notificações deseja receber;
- Quando deseja pausar ou encerrar o próprio monitoramento.

- Processando;
- Concluída;
- Falhou;

25. Decisões importantes
O MVP deve começar com:

Uma organização por conta;
Um bot oficial central criado e administrado pela empresa responsável;
Uma sessão isolada da conta pessoal do Telegram por organização;
A API de cliente do Telegram ou provedor compatível para autorização via QR Code;
A Telegram Bot API para notificações;
Um provedor de pagamento;
Regras simples de palavras-chave;
Notificações no site;
Notificações para o próprio cliente;
Histórico limitado;
Dashboard enxuto;
Sistema de auditoria;
Token do bot central fornecido pelo responsável e armazenado somente em secrets;
Sessões pessoais criptografadas, isoladas e revogáveis;
Conector da conta pessoal do Telegram substituível;
Conector da Telegram Bot API substituível;
Preços configuráveis;
Retenção de mensagens configurável.
O recurso mais delicado é a autorização via QR Code, o armazenamento seguro das sessões pessoais, o vínculo de cada grupo à organização correta, a leitura de mensagens e o envio de notificações pelo bot central.

Antes de comercializar a solução definitivamente, confirmar se a API de cliente do Telegram, o provedor escolhido e a Telegram Bot API permitem:

Configurar o bot oficial criado pela empresa responsável através do token fornecido pelo operador;
Armazenar o token somente em secrets, sem expô-lo ao cliente ou ao frontend;
Usar o mesmo bot oficial com isolamento rigoroso entre organizações;
Autorizar a conta pessoal do cliente via QR Code real e com expiração;
Armazenar, renovar e revogar a sessão pessoal com segurança;
Ler mensagens dos grupos acessíveis à conta pessoal autorizada;
Receber eventos da conta pessoal em tempo real ou por mecanismo estável equivalente;
Identificar o grupo de origem;
Processar mensagens de maneira estável;
Enviar notificações para o chat privado do próprio cliente pelo bot central;
Gerar links ou botões “Abrir mensagem” que respeitem a privacidade e o acesso ao grupo;
Operar comercialmente respeitando os limites e as políticas do Telegram;
Manter o bot e os mecanismos de atualização ativos;
Detectar sessão expirada, sessão revogada, conta desconectada, token revogado e falhas do bot corretamente;
Garantir que mensagens, grupos e alertas nunca sejam vinculados à organização errada.
